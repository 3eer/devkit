# 仮説検証 — 「AI委任力とマネジメント力は地続きの同一能力か」

> 検証対象の仮説（本人提示）: 人に依頼する力・任せる力・頼る力・伝える分量をコントロールする力は、相手がAIでも人でも同じ一つの判断力として働いているのではないか。
> 素材の制約: ローカルログはAI相手の判断が322件中の大半で、対人判断は41件（PRレビュアー対応、非エンジニア向け説明、顧客関係、読者設計など）。1on1・評価・OKRの直接記録は含まれない。
> 本文書は敵対的検証を1周通した改訂版。初版の「仮説は大筋で支持される」という結論は検証構造の欠陥（人側の観測ゼロ）を指摘され、格下げした。

## 結論（先に言う・改訂版）

**この素材では仮説は検証できない。言えるのは「AI相手の判断OSは、対人マネジメントの語彙で無理なく記述できる」ところまで。**

- AI側で観測された判断のOS（01の原理1〜7）は、委任・検収・段階委任・目的管理といった**マネジメントの概念で自然に記述できる**。この記述可能性自体が仮説と整合的であり、仮説を弱める材料は少ない。
- しかし「人相手でも同じOSが働いている」ことを示す観測はこの素材に**存在しない**。地続き表（後述）の「人相手での形」列はすべて推定であり、観測はAI側の列だけである。
- 「部下がAIエージェントに変わっただけ」（00[14]）という本人の発言は、仮説そのものを本人が言い換えたセルフイメージの表明であり、**証拠力はない**（検証したい仮説を本人が信じていることの証拠にしかならない）。
- 初版で「中核証拠」とした段階委任（レビュー通過率での自動化昇格、01[33]）は、宣言された理想であって実行の観測がなく、むしろ反例がある（01の「降格」節参照）。証拠から外した。
- 部分反証が1つある（後述）。これは素材内で実際に観測されたものであり、現時点で仮説に対する最も確度の高い知見はこの反証の方である。

**検証を完了させるには対人側の素材（claude.ai側の1on1・評価・OKR系の会話、または本人が書く実例）が必須。** 本文書の残りは「対人素材が来たときに何を突き合わせるか」の設計図として読むこと。

## 地続きと推定される部分（右列は観測済み、左列は未観測の推定）

| 対人マネジメントでの形（**推定・未観測**） | AI相手での形（**観測済み**) | 証拠 |
|---|---|---|
| 相手の力量・領域に応じた任せ方 | 正解の所在で手綱の長さを即時決定 | 00[56], 01メタ |
| 成果物で検収する | 実機・実出力で観測するまで未完了 | 01[08], 03[26] |
| 会議の脱線検知・目的回帰 | 「そもそも」による目的文への回帰 | 04[32], 00[32] |
| 指摘の采配（今/後で/やらない） | レビュー指摘を「本PR対応/Issue化/不要」に三分 | 04[23], 03[30] |
| 相手に合わせた説明の作り分け | 受け手別の成果物発注 | 01[49], 04[28] |
| お手本を見せる指導 | 却下と同時に自分が書いた見本を渡す | 05[19] |
| チームの慣行に合わせる | チームの検証記録テンプレ実物を貼って準拠させる | 04[29] |
| 信義の優先（利益相反・守秘） | 競合案件の即時除外、契約上発信不可の即断 | 00[06][12] |

最下行のみ注記: 信義の判断（00[06][12]）は対人・対顧客の判断そのものがログに現れた数少ない例であり、推定ではなく観測に近い。

**対人素材が来たときの検証手順**: 左列の各行について実例を1件以上集め、右列と同じ構造（問い→決定ルール）が働いているかを突き合わせる。一致すれば仮説は行単位で支持される。

## AI固有の部分（人へのマネジメントに対応物がないもの）

対人素材の有無にかかわらず、以下はAI相手にしか観測され得ない要素であり、仮説が正しくても「向け直し」では渡らない。

1. **試行コストゼロ前提の運用**。「確認が多すぎるな…全部画像作るようにスキルを修正して。確認は不要です」（01[26]）。多数の案を作らせて大半を捨てる運用は、人相手では士気の問題で不可能。人に対する遠慮の閾値を意図的にゼロへリセットする必要があり、これは向け直しではなく**解除**。
2. **記憶の外部化**。人間の部下は文脈を蓄積するが、AIはセッションで揮発する。resume時の完全な状態記述（04[08]）、CLAUDE.md憲法（04[07]）、スキルへの永続化（全チャンク）は、人マネジメントに対応物がない新規スキル。
3. **迎合の検知**。「あなたはだんだん私の意見が正しいといい始める」（03[10]）と同意の頻度自体を品質メトリクスとして監視し、「私の意見に引っ張られずに自分で考えて」（02[66]）と反アンカリングを明示する。**ただし重要な留保**: 本人自身が「〜ですよね？」と自分の傾きへの同意を求める誘導的な問い方を繰り返す癖があり（04メタ観察）、検知器は自分の仮説には向いていない。移転時は検知器と問い方の監査をセットにすること。
4. **遵守を前提にしない多層防御**。人には規範と信頼で任せる部分を、AIには「LLMは必ず守ることは保証されない」（03[07]）前提でhooks・Read deny・gitで技術的に封じる（01[51], 02[25][30]）。
5. **同時多重化**。「もう一度根本原因をチームを作って様々な観点から考えて」（04[27]）による同一知性の複製・並列化、モデル別の適材適所（文章はGemini、02[33]）。多視点でレビューを立てる発想自体は人の組織にも存在するが、人の組織ではコスト制約で実行できなかった規模を、AIでは制約なしに実行している（感覚の起源が人マネジメント由来か否かは素材からは判定できない）。

## 反証 — 素材内で実際に観測された、仮説への最も強い反対材料

**フィードバックの強度が相手によって完全に二系統に分かれている。** AIには「しね！」（01[11]）「ちゃんとやれよ」（05[34]）「アホか？」（00[18]）まで振れる一方、対人の記録では一貫して丁寧で、匿名化（05[43]）や退職者情報の除去（04[22]）など配慮が仕組み化されている。

これが意味するのは、本人の「手綱さばき」の実装の一部が**相手が感情を持たないことに依存している**ということ。少なくとも「AIへの接し方をそのまま人に向け直す」ことは絶対にできない。仮説の向き（人→AIへの向け直し）が成立する可能性は残るが、逆向き（AI→人）は観測事実として成立していない。**地続きだとしても一方通行である。**

もう1点。怒りの運用は原理ではなく本人のスタイルである（トリガーは「同じ指示の複数回無視」「却下理由の未反映」の2件にほぼ限定、05メタ・02メタ）。A氏に移転する際、この部分を「原理の一部」として渡すと事故になる。切り分けは 04 で扱う。

## 残る検証課題（対人素材が必要なもの・再掲強調）

1. 1on1・評価・育成方針の実判断で、原理1（正解の所在）が本当に同じ形で働いているか
2. OKR設計の取捨選択が、原理6（可逆性で順序を決める）と一致するか
3. 「伝える分量のコントロール」の対人実例 — AI相手では原理7（参照物で渡す・事後精密投入）だが、人相手で同じことをしているかはローカルログでは確認できない
4. 段階委任（通過率昇格）が対人の育成では実行されているか — AI側では宣言止まりだった（01降格節）。**もし対人側でも宣言止まりなら、それはそれで「理想と実運用の乖離が対象を問わず一貫している」という強い知見になる**
